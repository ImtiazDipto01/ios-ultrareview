# Security reports

Do not put credentials, private repositories, session logs, or exploitable sensitive details in a public issue.

For a sensitive vulnerability, use GitHub's **Security → Report a vulnerability** on this repository when available. Include the affected revision, reproduction steps, impact, and a minimal sanitized example. There is no guaranteed response time or paid support commitment.

The skill supplies instructions, not a sandbox. Agents and users must inspect trust boundaries before executing repository scripts. Evaluation access restrictions are task boundaries; unrestricted filesystem access can expose hidden fixtures. A freeze hash detects edits but does not authenticate the caller or model provider.
